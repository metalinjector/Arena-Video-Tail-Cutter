# Развёртывание Arena Video Tail Remover в Docker

Этот документ описывает, как упаковать и запустить сервис на любом независимом
сервере (VPS, выделенный сервер, локальная машина) с помощью Docker.

Сервис представляет собой **один контейнер**, внутри которого работает один
процесс Node.js (Express). Он одновременно:

- отдаёт собранный фронтенд (React) по корневому пути `/`;
- обслуживает API по пути `/api/*` (загрузка, обрезка, скачивание);
- вызывает системный `ffmpeg`/`ffprobe` для анализа и обрезки видео.

Базы данных и внешних сервисов **не требуется**.

---

## 1. Требования

На сервере должен быть установлен один из вариантов:

- **Docker** версии 20.10+ (для сборки нужен BuildKit, он включён по умолчанию);
- по желанию — **Docker Compose v2** (`docker compose`), чтобы запускать одной командой.

Проверка:

```bash
docker --version
docker compose version   # опционально
```

Минимальные ресурсы сервера: 1 vCPU / 1 ГБ RAM достаточно для одиночной
обработки. Так как `ffmpeg` нагружает процессор, для пакетной обработки
(до 10 файлов подряд) рекомендуется **2+ vCPU**. Обработка идёт строго по
одному файлу за раз, поэтому память расходуется экономно.

## 3. Быстрый запуск через Docker Compose (рекомендуется)

```bash
docker compose up -d --build
```

Что произойдёт:

1. Соберётся образ `arena-video-tail-remover:latest` (этап сборки + минимальный
   рантайм с `ffmpeg`).
2. Контейнер запустится в фоне и будет автоматически перезапускаться
   (`restart: unless-stopped`).
3. Сервис станет доступен на **http://<IP-сервера>:8080**.

Полезные команды:

```bash
docker compose logs -f          # смотреть логи
docker compose ps               # статус контейнера
docker compose down             # остановить и удалить контейнер
docker compose up -d --build    # пересобрать после обновления кода
```

### Изменить порт

По умолчанию хост-порт `8080` проброшен на внутренний `5000`. Чтобы открыть
сервис, например, на порту `80`, отредактируйте `docker-compose.yml`:

```yaml
    ports:
      - "80:5000"
```

и выполните `docker compose up -d`.

## 4. Запуск без Compose (чистый Docker)

Сборка образа:

```bash
docker build -t arena-video-tail-remover .
```

Запуск контейнера:

```bash
docker run -d \
  --name arena-video-tail-remover \
  --restart unless-stopped \
  -p 8080:5000 \
  arena-video-tail-remover
```

Управление:

```bash
docker logs -f arena-video-tail-remover     # логи
docker stop arena-video-tail-remover        # остановить
docker start arena-video-tail-remover       # запустить снова
docker rm -f arena-video-tail-remover       # удалить контейнер
```

## 5. Конфигурация (переменные окружения)

| Переменная   | По умолчанию  | Назначение                                              |
|--------------|---------------|--------------------------------------------------------|
| `PORT`       | `5000`        | Порт, который слушает процесс внутри контейнера.        |
| `PUBLIC_DIR` | `/app/public` | Путь к собранному фронтенду. Менять не нужно.           |
| `NODE_ENV`   | `production`  | Режим работы (влияет на формат логов).                  |
| `LOG_LEVEL`  | `info`        | Уровень логирования: `debug`, `info`, `warn`, `error`. |

> Лимит размера загружаемого файла — **50 МБ на файл** — задан в коде
> (`artifacts/api-server/src/routes/trim.ts`, поле `fileSize`, и в константе
> `MAX_SIZE_MB` на фронтенде `artifacts/video-trimmer/src/App.tsx`). Чтобы его
> изменить, поправьте оба места и пересоберите образ.

В образ встроен `HEALTHCHECK`, опрашивающий `/api/healthz`. Состояние видно так:

```bash

```

Откройте `http://<IP-сервера>:8080` в браузере — должна загрузиться страница
загрузки видео.

## 7. Хранилище временных файлов

Во время обработки сервис создаёт во внутренней папке контейнера каталоги
`tmp-uploads` и `tmp-outputs`. Загруженный файл удаляется сразу после обрезки,
а результат — через короткое время после скачивания.

В `docker-compose.yml` эти каталоги вынесены в `tmpfs` (ОЗУ), чтобы не изнашивать
диск и гарантированно очищать данные при перезапуске. Если памяти мало, удалите
блок `tmpfs` — тогда временные файлы будут лежать в слое контейнера.

## 8. HTTPS и доменное имя (рекомендуется для продакшена)

Сам контейнер отдаёт обычный HTTP. Для доступа по домену с сертификатом
поставьте перед ним обратный прокси. Пример для **Nginx**:

```nginx
server {
    listen 80;
    server_name your-domain.com;

    # Разрешаем загрузку файлов до 50 МБ (с запасом).
    client_max_body_size 60M;

    location / {
        proxy_pass         http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;

        # Видео могут обрабатываться долго — увеличиваем таймауты.
        proxy_read_timeout    600s;
        proxy_send_timeout    600s;
    }
}
```

Бесплатный сертификат Let's Encrypt можно выпустить с помощью `certbot`:

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

> Важно: при использовании прокси обязательно поднимите лимит размера тела
> запроса (`client_max_body_size`), иначе загрузка крупных видео будет
> прерываться с ошибкой 413.

## 10. Диагностика

| Симптом                                   | Что проверить                                                                 |
|-------------------------------------------|------------------------------------------------------------------------------|
| Страница не открывается                   | `docker ps` — запущен ли контейнер; правильный ли проброс портов `-p`.        |
| `ffmpeg: not found` в логах               | Пересоберите образ — `ffmpeg` ставится на этапе рантайма из этого Dockerfile. |
| Ошибка 413 при загрузке                   | Поднимите `client_max_body_size` в Nginx и/или лимит 50 МБ в коде.            |
| Видео загружается, но «хвост» не найден    | Файл короче порога либо хвост не совпадает с эталоном `ref_tail.mp4`.         |
| Долгая обработка / высокая нагрузка на CPU | Это `ffmpeg`. Добавьте vCPU; пакетная обработка идёт последовательно.         |

Логи всегда доступны командой:

```bash
docker compose logs -f          # или: docker logs -f arena-video-tail-remover
```

## Архитектура образа (кратко)

- **Многоэтапная сборка.** На этапе `builder` (`node:24-bookworm`) ставятся
  зависимости через `pnpm` и собираются бэкенд и фронтенд.
- Бэкенд собирается `esbuild` в **самодостаточный** файл `dist/index.mjs` —
  поэтому в финальном образе **не нужен** `node_modules`.
- Финальный образ (`node:24-bookworm-slim` + `ffmpeg`) содержит только бандл
  бэкенда, эталонный клип `src/reference-frames/ref_tail.mp4` и собранный
  фронтенд в `/app/public`. Это делает образ компактным и быстрым в запуске.
