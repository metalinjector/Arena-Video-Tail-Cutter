# Video Tail Remover

Сервис для автоматического обнаружения и удаления повторяющегося «хвоста» (одинакового
концевого фрагмента видео), который добавляется некоторыми генераторами видео в конец
каждого файла. Пользователь перетаскивает или выбирает видеофайл — сервис находит границу
хвоста, отрезает его и отдаёт готовый файл на скачивание уже без лишнего фрагмента.

---

## Что делает сервис

Некоторые программы при генерации видео добавляют в конец каждого файла один и тот же
короткий фрагмент (~5 секунд). Этот фрагмент идентичен от файла к файлу, но «полезная»
часть видео перед ним имеет разную длину. Сервис:

1. Принимает видео (drag-and-drop или выбор файла).
2. Определяет в конце файла границу, с которой начинается типовой хвост.
3. Покадрово точно отрезает хвост (включая его самый первый кадр), не теряя полезные кадры.
4. Возвращает итоговый файл на скачивание.

### Проверенные примеры

| Файл                              | Исходная длина | После обрезки | Удалено |
|-----------------------------------|----------------|---------------|---------|
| `ltx-2-19b_b_Make_person_alive`   | 13.96 c        | ровно 9.00 c  | 4.96 c  |
| `kling-v3_a_Make_person_alive`    | 10.04 c        | ровно 5.00 c  | 5.04 c  |

## Как работает обнаружение хвоста

Хвост — это всегда один и тот же видеоклип. При первой настройке из образца был извлечён
эталонный фрагмент начала хвоста (`ref_tail.mp4`). Алгоритм сравнивает окончание
загруженного видео с этим эталоном по метрике **SSIM** (структурное сходство кадров) в две
фазы:

1. **Грубый поиск.** Перебираются несколько смещений от конца файла
   (3.5 / 4.0 / 4.5 / 4.75 / 5.0 / 5.25 / 5.5 / 6.0 с) и выбирается то, где сходство с
   эталоном максимально. Это даёт приблизительную зону начала хвоста.
2. **Точный (покадровый) поиск.** Вокруг найденной зоны выполняется проход с шагом в один
   кадр, чтобы найти точный кадр, с которого начинается хвост. Частота кадров определяется
   индивидуально для каждого файла (`r_frame_rate`), поэтому длительность одного кадра
   вычисляется корректно для любого fps.

Точка разреза ставится на полкадра раньше первого кадра хвоста — так весь хвост (включая его
первый кадр) удаляется гарантированно, но при этом не теряется ни один полезный кадр.

Обрезка выполняется **с перекодированием** (`libx264`, CRF 18, AAC 192k), потому что простое
копирование потока (`-c copy`) режет только по ключевым кадрам и оставляет «лишние» кадры
хвоста. Перекодирование обеспечивает покадрово точный разрез.

Если сходство с эталоном ниже порога (хвост не найден), используется запасное значение —
обрезка последних ~5 секунд.

## Структура проекта

Проект — это монорепозиторий на **pnpm workspaces**.

```
.
├── artifacts/
│   ├── api-server/                  # Бэкенд (Express 5)
│   │   ├── src/
│   │   │   ├── app.ts               # Конфигурация Express
│   │   │   ├── routes/
│   │   │   │   ├── index.ts         # Подключение маршрутов
│   │   │   │   ├── health.ts        # Health-check
│   │   │   │   └── trim.ts          # ★ Логика обнаружения и обрезки хвоста
│   │   │   └── reference-frames/
│   │   │       └── ref_tail.mp4     # Эталонный фрагмент начала хвоста
│   │   └── build.mjs                # Сборка через esbuild
│   ├── video-trimmer/               # Фронтенд (React + Vite)
│   │   └── src/
│   │       ├── App.tsx              # ★ Интерфейс: загрузка, статус, скачивание
│   │       └── index.css           # Тема оформления
│   └── mockup-sandbox/              # Служебный артефакт (не относится к сервису)
├── lib/                             # Общие библиотеки монорепо
├── scripts/                         # Утилитарные скрипты
├── package.json                     # Корневая оркестрация задач
└── pnpm-workspace.yaml              # Описание workspace-пакетов
```

Ключевые файлы сервиса:
- **`artifacts/api-server/src/routes/trim.ts`** — серверная логика: приём файла, определение
  границы хвоста, обрезка, выдача результата.
- **`artifacts/video-trimmer/src/App.tsx`** — интерфейс пользователя.
- **`artifacts/api-server/src/reference-frames/ref_tail.mp4`** — эталон хвоста для сравнения.

## API

### `POST /api/trim`
Принимает `multipart/form-data` с полем `video` (видеофайл).
Возвращает JSON:
```json
{
  "id": "uuid",
  "filename": "имя_trimmed.mp4",
  "originalDuration": 13.96,
  "trimmedDuration": 9.0,
  "removedSeconds": 4.96
}
```

### `GET /api/download/:id?filename=...`
Отдаёт готовый обрезанный файл на скачивание. Файл автоматически удаляется через 60 секунд
после скачивания.

### `GET /api/healthz`
Проверка состояния сервера: `{ "status": "ok" }`.

## Технологический стек

- **pnpm workspaces**, Node.js 24, TypeScript 5.9
- **Бэкенд:** Express 5, `multer` (загрузка файлов), `uuid`
- **Обработка видео:** FFmpeg / FFprobe (вызываются как внешний процесс)
- **Фронтенд:** React + Vite, `react-dropzone`, Tailwind CSS
- **Сборка бэкенда:** esbuild

> **Важно:** на сервере должен быть установлен **FFmpeg** (с `ffmpeg` и `ffprobe` в `PATH`).
> Без него обработка видео работать не будет.

## Запуск

Требуется установленный `pnpm` и `ffmpeg`.

```bash
# 1. Установить зависимости
pnpm install

# 2. Запустить бэкенд (по умолчанию слушает порт из переменной PORT)
pnpm --filter @workspace/api-server run dev

# 3. В отдельном терминале запустить фронтенд
pnpm --filter @workspace/video-trimmer run dev
```

Фронтенд обращается к бэкенду по относительным путям `/api/*`, поэтому в продакшене оба
сервиса должны быть доступны за общим обратным прокси (frontend на `/`, API на `/api`).

### Проверка типов и сборка

```bash
pnpm run typecheck   # проверка типов по всем пакетам
pnpm run build       # сборка всех пакетов
```

## Настройка под свой хвост

Если типовой хвост отличается от заложенного эталона, замените файл
`artifacts/api-server/src/reference-frames/ref_tail.mp4` на первые ~2 секунды вашего хвоста:

```bash
# извлечь 2 секунды, начиная с момента начала хвоста (пример: с 9-й секунды)
ffmpeg -ss 9.0 -i ваш_образец.mp4 -t 2 -c copy ref_tail.mp4
```

Параметры в `artifacts/api-server/src/routes/trim.ts`:
- `TAIL_DURATION_S` — ожидаемая длина хвоста (запасное значение).
- `SEARCH_OFFSETS_S` — смещения для грубого поиска.
- `SSIM_THRESHOLD` — порог сходства, при котором хвост считается найденным.
